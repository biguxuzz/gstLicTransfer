# GstLicTransfer — расширение для 1С:Бухгалтерия предприятия 3.0

Расширение `GstLicTransfer` для БП 3.0.195.40. Назначение: оформление и
печать актов приема-передачи программных продуктов 1С (передача лицензий)
между контрагентами по конструируемым шаблонам.

## Состав расширения

- **Документ.ПередачаЛицензий** — акт приема-передачи программных продуктов:
  - Реквизиты: `Организация` (Справочник.Организации),
    `КонтрагентПередающий` / `КонтрагентПринимающий`
    (Справочник.Контрагенты), `Автор` (Справочник.Пользователи),
    `Комментарий`;
  - Табличная часть `ПередаваемыеПродукты`: `Продукт` (строка 250),
    `РегистрационныйНомер` (строка 50);
  - без движений по регистрам (сервисный документ).
- **Справочник.ШаблоныПередачиЛицензий** — конструктор шаблонов акта.
  Принцип повторяет типовой механизм печати договоров
  (Справочник.ШаблоныДоговоров):
  - шаблон — HTML в реквизите `ШаблонХранилище` (ХранилищеЗначения,
    структура `{ТекстHTML, Вложения}`);
  - параметры в тексте — `{ИмяПараметра}` на жёлтом фоне;
  - редактор шаблона — поле форматированного документа с меню
    «Вставить параметр» (документ, организация, передающий, принимающий);
  - макет-прототип `АктПриемаПередачиПродуктов1С` (HTMLDocument)
    на основе типовой формы акта.
- **Общие модули** `ПечатьАктовПередачиЛицензий` (сервер) и
  `ПечатьАктовПередачиЛицензийКлиент` — заполнение шаблона данными
  документа и запуск печати.
- **Подсистема.ПередачаЛицензий** — раздел интерфейса.
- **Роль.GstLicTransferОсновнаяРоль** — права на объекты расширения.

### Подключение к подсистемам БСП

- **Печать** — команда печати зарегистрирована по стандарту БСП:
  `ДобавитьКомандыПечати()` в модуле менеджера документа + обработчик
  `ПечатьАктовПередачиЛицензийКлиент.ВыполнитьКомандуПечати`; в формах
  документа и списка вызывается `ПодключаемыеКоманды.ПриСозданииНаСервере`.
- **Версионирование объектов** — доступно штатной настройкой БСП
  («Администрирование → Общие настройки → Версионирование объектов»),
  метаданных от документа не требует.
- **Даты запрета изменения** — действуют автоматически (подписки БСП на
  все документы).
- **Присоединенные файлы** — не подключены (потребовал бы заимствования
  подсистемы ПрисоединенныеФайлыБП и 485 типовых справочников-прототипов;
  противоречит принципу минимального наследования).

## Сборка

CI на GitHub Actions собирает `.cfe` автоматически при пуше в `main`.
Результат — release с тегом `v<версия>` и артефакт
`GstLicTransfer_<версия>.cfe`.

### Версионирование

Схема `WW.XX.YY.ZZZ`:
- `WW` — меняется при смене версии конфигурации БП (вручную)
- `XX` — добавлены новые объекты/бизнес-логика (вручную)
- `YY` — изменена бизнес-логика, объекты те же (вручную)
- `ZZZ` — инкрементируется при любой сборке (автоматически в CI)

Версия хранится в `Configuration.xml` в теге `<Version>`. CI инкрементирует
`ZZZ` через regex-замену (без нормализации XML) и коммитит обратно в репо
от имени `github-actions[bot]` с маркером `[skip ci]`.

### Локальная сборка через ibcmd

```pwsh
ibcmd infobase --data=.\server-data --db-path=file-db create --import=buildcf --apply --force
ibcmd infobase --data=.\server-data --db-path=file-db config import --extension=GstLicTransfer .
ibcmd infobase --data=.\server-data --db-path=file-db config save --extension=GstLicTransfer .\binary\GstLicTransfer.cfe
```

## buildcf/

Каталог `buildcf/` содержит родительскую конфигурацию (заглушки каталогов
Организации, Контрагенты, Пользователи из БП 3.0.195.40) для сборки
расширения. Расширение **не заимствует** объекты основной конфигурации:
типы каталогов используются только в реквизитах, поэтому в buildcf
достаточно их XML-заглушек с оригинальными UUID.

### Обновление buildcf

При добавлении новых ссылок на типы основной конфигурации — обновить
таблицу UUID в `buildcf/_generate.py` и запустить:

```bash
python buildcf/_generate.py
```

Скрипт копирует оригиналы из `E:\temp\acc\` (выгрузка БП) и понижает
XCF version 2.21 → 2.20 (требование 1С 8.3.27 на CI).

## Секреты GitHub Actions

- `ONEC_USERNAME` / `ONEC_PASSWORD` — учётка для скачивания платформы 1С
  (используются `1CDevFlow/onec-setup-action`).

## Использование

1. Подключите расширение к базе БП (Администрирование → Расширения).
2. В разделе «Передача лицензий» создайте шаблон акта
   (Справочник.ШаблоныПередачиЛицензий) — на основании типового макета
   или с нуля; при необходимости отредактируйте текст и вставьте
   нужные параметры через меню «Вставить параметр».
3. Создайте документ «Передача лицензий», заполните стороны и список
   продуктов, нажмите «Печать акта», выберите шаблон — будет открыт
   заполненный акт; печать — штатными средствами поля форматированного
   документа (печать/предварительный просмотр).

Пример печатной формы — `Акт-приема-передачи-продуктов1С.docx` в корне
репозитория.
